# 用户材料挖掘规则

## 一、识别材料

判断材料属于新闻、政策文件、会议纪要、调研记录、访谈、专家观点、行业报告、基层观察或个案线索。

材料不足时先完成初步发掘，再列出缺口；不要只停留在泛泛追问。

## 二、提取确定信息

按以下栏目整理，未出现的标记“材料未提供”：

- 发生了什么
- 涉及谁
- 在什么场景发生
- 已造成或可能造成什么影响
- 有哪些数据、案例、政策表述或直接引语
- 哪些是事实，哪些是当事人观点，哪些只是推测
- 是否存在反常、矛盾、落差、空白或执行堵点

这一步只做事实分层，不提出建议。

## 三、从六个视角寻找切口

1. **政策落差**：政策目标与基层执行结果是否存在落差。
2. **机制堵点**：是否存在职责不清、多头管理、监管空白或协同失灵。
3. **新兴风险**：新技术、新业态、新模式是否带来现有规则尚未覆盖的风险。
4. **群体影响**：某类人群、行业或地区是否受到集中、持续或不成比例的影响。
5. **趋势苗头**：个案是否可能反映正在扩大的趋势或尚未被重视的苗头。
6. **地方切口与上级价值**：地方现象能否反映更高层级共性问题；上级政策是否在地方出现具体堵点。

只保留与材料真正相关的方向，避免换一种方式复述文章标题。

## 四、形成候选方向

默认提出 3—5 个方向。标题优先采用“对象或现象 + 风险或堵点 + 亟待采取的方向”结构，不得为吸引注意夸大风险。

每个方向说明：

- 材料中的触发事实
- 深层机制切口
- 涉及群体与公共影响
- 为什么值得现在关注
- 报送层级
- 证据缺口
- 哪些结论目前不能写

## 五、特殊情形

- **只有一个个案**：可以发掘制度性切口，但必须提示代表性不足，并设计验证同类情况的问题。
- **只有观点没有事实**：把观点作为待验证假设，不得直接形成结论。
- **数据没有出处**：可以作为线索，不得作为确定依据。
- **标题结论强于正文证据**：降低判断强度，回到材料能够支撑的表述。
- **材料包含敏感个人信息**：隐藏不必要的姓名、联系方式、证件号等信息。
- **切口过于宏大**：补齐“谁、在哪个环节、受到什么影响、由谁负责”四个要素。

## 六、后续联网边界

用户没有要求联网时，不用材料外事实填补空白，只列出“建议核查的政策、数据、案例和部门”。

用户要求核验或扩展时，转入混合模式：

1. 把材料事实作为搜索种子；
2. 优先核对政策原文、统计数据和同类案例；
3. 将用户材料、联网确认、合理推断分别标记；
4. 不因搜索到相似报道就直接证明该问题具有普遍性。
